# GPT 中转（GPT Relay）

一个 Android 客户端：**用你自己提供的机场订阅，把 GPT 网页 / 接口接进 App 里直接对话**。

原生聊天界面 + 侧边栏配置，内置代理核心（Xray），支持 Clash 与通用订阅格式，
并提供「网页模式」（在 WebView 里跑真实网页并把页面消息转发到原生界面）与
「接口模式」（直连 OpenAI 兼容接口）两种运行方式。

> ⚠️ **使用前请务必阅读文末的[免责声明](#免责声明)。**

## 用途

本项目解决的是一个具体问题：

- 你手上有**机场订阅**（vmess / vless / trojan / shadowsocks），想让 GPT 走这条线路；
- 你不想在浏览器、代理客户端、聊天工具之间来回切换；
- 你希望**一个 App 内**完成「连线路 → 聊天」。

它做了三件事：

1. **订阅解析**：拉取订阅地址，解析成节点列表（Clash YAML、base64、明文 URI 三种格式）。
2. **本地代理**：把内置核心作为子进程拉起，在本机开本地入站，不接管系统全局流量。
3. **对话界面**：
   - **网页模式**：WebView 加载真实网页，注入守望脚本把页面对话**转发**到原生界面；
   - **接口模式**：直接调 OpenAI 兼容接口（流式输出），请求经本地代理出网。

## 功能

| 模块 | 说明 |
|---|---|
| 订阅解析 | Clash / Clash Meta YAML（区块 + 流式两种写法）、base64、明文 URI 列表 |
| 协议支持 | vmess / vless（含 REALITY）/ trojan / shadowsocks |
| 节点管理 | 解析结果缓存、节点选择、失败时给出**可诊断**的详细原因 |
| 本地代理 | 内置核心以子进程运行，SOCKS5（2080）+ HTTP（2081）双入站 |
| 网页模式 | 多组选择器兜底抓取页面对话，流式转发到原生界面；支持弹窗接管（OAuth 登录不中断） |
| 接口模式 | OpenAI 兼容接口，SSE 流式输出 |
| 界面 | 深色极光背景 + 液态玻璃面板，侧边栏抽屉配置 |
| 诊断 | 一键复制「实际生成的配置 + 核心错误日志 + 订阅响应摘要」 |

## 使用

### 1. 安装

从 Releases 下载 APK 安装（仅打包 `arm64-v8a`，对应绝大多数现代 Android 手机）。

### 2. 配置机场

打开 App → 左上角 **☰** 打开侧边栏 → **机场订阅**：

1. 填入你的订阅地址；
2. 点 **拉取并解析**；
3. 状态栏会显示识别到的格式与节点数量；
4. 在 **节点** 下拉里选一个节点；
5. 点 **连接**。

> 若解析出 0 个节点，状态栏会给出**响应开头 220 字**与识别结果，按此判断订阅格式。

### 3. 选择运行方式

侧边栏顶部 **运行方式**：

- **网页模式**（默认）：用真实网页，**不需要 API Key**。
  - 首次可能需要登录；登录弹窗会被接管，流程不会中断。
  - 页面对话会以流式方式转发到原生界面。
  - 顶栏 **🌐** 可在「转发的消息」与「网页本体」之间切换。
  - 若转发不出消息，点 **🔁 重扫**；状态栏会报告命中的选择器与节点数。
- **接口模式**：直连 OpenAI 兼容接口，**需要 API Key**。
  - 在 **接口配置** 里填 Base URL、API Key、模型名 → **保存**。

### 4. 开始对话

在底部输入框输入内容 → **发送**。

- 网页模式：文字会被填入网页输入框并触发发送；
- 接口模式：直接流式调用接口。

### 5. 出问题时

侧边栏 → **状态** → **复制诊断信息（配置 + 日志）**。
复制内容包括：引擎、节点数、已选节点、实际生成的 `config.json`、核心错误日志。
把它贴出来即可定位问题。

## 运行原理

```
聊天请求（OkHttp）──SOCKS5──┐
                            ├──► 内置核心（Xray 子进程）──► 你的机场线路 ──► 目标站点
网页模式（WebView）──HTTP───┘
```

几点说明：

- **不接管系统全局流量**：只代理本 App 自身的请求，不影响手机其它应用。
  这是刻意的设计选择——全局代理需要 `VpnService` + tun2socks，是另一个量级的工作。
- **核心以子进程方式运行**：二进制放在 `jniLibs` 里伪装成 `libxray.so`。
  原因是 Android 10+ 禁止从应用数据目录执行文件，而系统会把 native 库解压到
  可执行的 `nativeLibraryDir`，这是唯一稳妥的落点。
- **为什么用 Xray 而不是 sing-box**：sing-box 的网络管理器在启动时会为网卡监控建立
  **netlink 多播订阅**，而这需要 `CAP_NET_ADMIN`——Android 普通应用没有，于是启动即
  `FATAL start service: subscribe route updates: permission denied`。
  Xray 默认不监控网卡，可正常作为子进程运行。

## 从源码构建

### 依赖

- JDK 17
- Android SDK：`platforms;android-35`、`build-tools;35.0.0`
- Gradle 8.11.x
- 核心二进制（**未随仓库分发**，需自行获取，见下）

### 获取核心

仓库**不包含**第三方代理核心二进制（体积与许可证原因）。
运行脚本自行下载：

```bash
bash scripts/fetch-core.sh
```

脚本会把 Xray-core 的 Android arm64 构建放到
`app/src/main/jniLibs/arm64-v8a/libxray.so`。

### 构建

```bash
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
./gradlew :app:assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`

### 在 aarch64 Linux 上构建的注意事项

Google **不发布** linux-aarch64 的 build-tools，而 `aapt2` 是 x86_64 原生二进制。
若在 ARM Linux（例如手机上的容器）构建，需要用 QEMU 模拟：

```bash
apt-get install -y qemu-user-static
dpkg --add-architecture amd64
# 添加 amd64 源后安装 x86_64 运行库
apt-get install -y libc6:amd64 libstdc++6:amd64 zlib1g:amd64
# 再把 build-tools 里的 x86_64 原生工具包一层 qemu 外壳
```

并在 `gradle.properties` 中指定重定向：

```properties
android.aapt2FromMavenOverride=/path/to/sdk/build-tools/35.0.0/aapt2
```

## 已知限制

- **仅 arm64-v8a**：32 位设备不支持。
- **仅代理本 App**：不接管系统全局流量（见「运行原理」）。
- **网页模式的转发依赖页面结构**：已用多组选择器兜底，但目标站点若改动 DOM，
  可能需要在 `WebEngine.kt` 的 `SELECTORS` 中补充。状态栏会报告命中情况。
- **Xray 不支持 hysteria2 / tuic**：选中这类节点时会明确提示换节点。
- **外部浏览器登录无法回传**：系统浏览器的 Cookie 与本 App 的 WebView 沙盒相互隔离，
  Android 没有跨应用读取 Cookie 的接口。因此网页模式**必须在本 App 内完成登录**。
